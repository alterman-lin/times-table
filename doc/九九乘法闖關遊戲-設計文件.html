1背景與需求脈絡

使用者想要一個幫助學生練習九九乘法的網頁遊戲。這是全新專案（E:\教育\小遊戲\99 目前是空資料夾，非 git repo），因此不需要相容既有程式碼，可以自由選擇最單純、最容易開啟與維護的架構。

核心教學設計是「難度漸進」：先用不限時的是非題、選擇題建立信心，再用自行輸入答案訓練回想能力，最後加上時間壓力（限時版的是非題/選擇題/輸入題）模擬熟練度測驗。每關過關（10 題對 7 題以上）發放金幣，金幣可在商店購買服裝配件，全破關時角色會穿上所有已購買的裝備；若玩家中途放棄，角色會呈現落魄樣。這個「養成/裝扮」機制是額外的正向回饋，用來提升學生反覆練習的動機。

已與使用者確認的關鍵行為

  • 關卡失敗處理：兩種都要。失敗（10 題對 <7 題）時彈出選擇：「重新挑戰本關」（換一組新題目重考同一關）或「結束本局，看落魄結局」（結束本次遊戲，角色顯示落魄樣，並可重新開始）。
  • 頭像產生方式：先用預設圖示/SVG 角色的概念設計，實際美術外觀（頭像選項、配色、服裝插畫風格）留到真正動工時再與使用者討論確認，現在只需把系統設計成「可替換美術資源」的架構。

2技術方案

純前端、零建置、零伺服器依賴的靜態網頁遊戲，方便老師/學生直接雙擊開啟或丟上任何靜態空間：

  • index.html — 遊戲外殼，所有畫面（建立角色、關卡地圖、作答、商店、結算、結局）用一組 <section> 切換顯示/隱藏，不用框架、不用路由。
  • css/style.css — 明亮童趣風格、響應式（手機/平板/桌機皆可玩），是非題/選擇題/數字鍵盤三種作答 UI 的樣式。
  • js/questions.js — 九九乘法題目產生器：依關卡型態產生是非題（含刻意答錯的干擾式）、選擇題（含常見錯誤的三個誘答選項）、輸入題（純數字），確保 10 題不重複。
  • js/game.js — 遊戲狀態機：管理目前玩家、關卡序列（6 關）、計時器、答題判分、過關/失敗分支、金幣結算。
  • js/character.js — 角色渲染：base 角色（SVG 分層）+ 依 equipped 狀態疊加服裝圖層；另外提供「落魄」外觀（灰階/破損疊圖）。
  • js/shop.js — 商店資料（衣服／裙子／褲子／包包／飾品／鞋子六個欄位的品項、價格、對應圖層 id）與購買/穿脫邏輯。
  • js/storage.js — localStorage 存讀：玩家名單（名字+頭像選擇）、單局進度（目前關卡、金幣、擁有品項、已裝備品項、各關分數）。

不需要後端、不需要帳號系統；資料只存在使用者自己瀏覽器的 localStorage。

3關卡與遊戲流程

  1. 建立角色畫面

    輸入名字、從預設圖示中選頭像（之後可擴充上傳照片，本次先不做），「開始遊戲」。可從清單挑選/刪除既有玩家紀錄以支援多人共用同一台電腦。

  2. 關卡地圖畫面

    顯示 6 關路徑（不限時是非題 → 不限時選擇題 → 不限時輸入題 → 限時是非題 → 限時選擇題 → 限時輸入題），未達成的關卡鎖定，已過關顯示星星/勾勾，同時顯示目前金幣與角色小預覽。

  3. 作答畫面

    每關 10 題，共用同一套流程，依型態切換 UI 元件：

    • 是非題：顯示一個乘法算式（真/假各半機率），按「對」/「錯」。
    • 選擇題：顯示 a × b = ?，四選一（1 正解 + 3 常見錯誤誘答）。
    • 輸入題：a × b = ?，畫面內建數字鍵盤（0-9、清除、送出），不依賴實體鍵盤，觸控裝置也能玩。
    • 限時關卡（第 4-6 關）在上述三種 UI 上疊加每題倒數（例如是非/選擇 15 秒、輸入 20 秒，可於 game.js 常數調整），超時視為答錯並自動進下一題。
  4. 關卡結算
    • 過關（≥7/10）：慶祝動畫、發放金幣（基礎值 + 每題對值，限時關卡加成），按鈕「前往商店」與「下一關」。
    • 失敗（<7/10）：依需求彈出兩個選項——
      • 「重新挑戰本關」：換一組新的 10 題，重考同一關，進度與已購買物品不變。
      • 「結束本局」：進入落魄結局畫面（角色套用落魄外觀），並提供「重新開始」以新局重來（金幣與購買物品重置，名字/頭像可沿用）。
  5. 商店畫面

    每次過關後可進入（也可略過先繼續下一關再回來逛）。六個裝備欄位各自列出可購買品項與價格，已擁有標示「已擁有」，同欄位若擁有多件可切換裝備哪一件。角色即時預覽會反映目前裝備狀態。

  6. 結局畫面
    • 全破 6 關：完整角色圖，身上穿著六個欄位目前裝備的所有品項（= 玩家買到的東西都穿在身上），顯示過關統計（正確率、用時、獲得金幣），可「重新開始」再玩一輪。
    • 中途放棄：角色套用「落魄」外觀（例如灰階/破舊疊圖 + 沮喪表情），鼓勵訊息 + 「重新開始」。

4資料設計重點

題目池：1–9 × 1–9 共 81 組，每關隨機抽 10 題且關內不重複；是非題錯誤選項用「答案加減一個小偏移」產生，選擇題誘答用常見錯誤（相鄰的九九乘法結果、任一因數 ±1 的結果）產生，避免明顯不合理的選項。

過關門檻固定 7/10，全部 6 關皆同一標準。

金幣與商店品項只是概念性數字/清單，實際數值與品項美術在 js/shop.js 內以資料表方式定義，方便之後調整難度曲線與服裝內容而不用改邏輯程式。

角色美術先用可替換的分層 SVG／色塊佔位，正式素材風格（頭像清單長相、服裝插畫）留到實作階段再與使用者確認，不在本次規劃內鎖定。

81 組題目 7 / 10 過關門檻 6 個裝備欄位 分層 SVG 角色

5驗證方式

專案無需建置，直接用瀏覽器開啟 index.html（或透過 preview_start 起一個靜態伺服器）手動走過整條流程：

  1. 建立角色（輸入名字、選頭像）。
  2. 依序完成不限時是非題／選擇題／輸入題三關，確認數字鍵盤在滑鼠與觸控模擬下都可用。
  3. 故意在某一關答錯 4 題以上，確認「重新挑戰本關」與「結束本局看落魄結局」兩個分支都能正確運作。
  4. 完成限時三關，確認倒數計時、超時自動判錯與跳題邏輯正確。
  5. 每次過關後進商店購買品項，確認金幣扣款、已擁有標示、裝備切換即時反映在角色預覽上。
  6. 全破 6 關，確認結局畫面角色身上顯示所有目前裝備的品項；另開一輪測試中途放棄的落魄結局畫面。
  7. 用瀏覽器工具切換手機尺寸，確認版面與按鈕可正常操作。

男孩「改裝愛車」主線

雙軌並行：不改動既有女生線，新增一條給男孩玩家的平行故事

6男孩線：背景與需求

原本的遊戲（Part 1）只有「甜心少女」美術主題，服裝商店的養成回饋對男孩玩家吸引力有限。這次新增一條平行的男孩故事線：選一位男孩角色後，答對關卡不是拿金幣買衣服，而是直接把畫面上那台「男孩坐在裡面」的車，隨著每過一關自動變得更好——從沒氣輪胎的破車，一路修到全新拉風跑車。

核心九九乘法答題引擎（題目產生、是非/選擇/輸入三種作答 UI、計時器、過關判定）完全與美術/獎勵主題無關，100% 原封不動重用；只有「選角色」與「過關後看到什麼」這兩塊依故事線分岔。

7男孩線：設計決策

  • 先選故事、再選角色：新增最前面的「選故事」畫面（既有玩家名單 + 「甜心少女的故事」/「改裝小車手的故事」兩張故事卡），選完故事才進入建立角色畫面，該畫面依故事只顯示對應的 3 個頭像。
  • 完全沒有金幣/商店：車子的每個改裝階段純粹由「已過幾關」自動解鎖，不用買、不用花錢——男孩玩家全程看不到金幣數字。
  • 烤漆顏色（3 選 1）可以隨時重選：不是一次性鎖定，開一個「改裝車庫」畫面讓男孩玩家隨時免費切換，即點即生效、不需要確認對話框。
  • 3 位男孩、各自一台專屬的車：不是共用同一台車換色，而是各自獨立的車型設計，個人化程度最高，美術量也最大。
  • 第六關的終極獎勵跑車，顏色不用跟著前面選的烤漆色：當成「有人送你一台全新的車」的驚喜獎勵處理，用文案把「顏色換了」講成故事的一部分，省下 18 張色彩對應圖。
  • 中途放棄顯示「目前進度的車 + 灰階濾鏡」：不是重置回破爛車，呼應既有女生線「小熊在這裡等你回來」的鼓勵基調——放棄不等於進度歸零，只是車先停在車庫蒙灰。

8男孩線：資料與新增檔案

玩家資料（js/storage.js）新增兩個欄位：track（'girl' 或 'boy'，建立角色時決定，之後不可更改）與 carColor（null 或選定的顏色 id，重新開始時清空）。金幣/服裝欄位對男孩玩家仍然存在但永遠不顯示、不使用——過關判定那段程式碼是全遊戲最關鍵的一段，寧可多留一個沒用到的數字，也不要為了「完全拿掉」去冒風險改動它。

車子改裝階段純粹由「已過幾關」算出（0～6 關全過對應 0～6 階段），不用另外存一個進度值。

  • js/car.js（新檔案）— 男孩線的渲染邏輯：依「男孩 id + 目前階段 + 烤漆顏色」算出要顯示哪張圖、套用灰階濾鏡；同時提供選角頭像用的裁切來源。架構完全比照既有 js/character.js 的角色渲染方式，兩者互不干涉。
  • js/game.js — 新增「選故事」畫面邏輯、「改裝車庫」畫面邏輯、烤漆顏色選色元件；既有的地圖/結算/商店/結局渲染全部改走同一個「依故事線分派」的入口，確保沒有漏改的地方讓男孩角色顯示成女生。
  • index.html — 新增「選故事」畫面與「改裝車庫」畫面；建立角色畫面的頭像清單從 3 張擴充成 6 張（3 女生 + 3 男孩，依故事顯示對應 3 張）。
  • css/style.css — 只新增「烤漆顏色選色球」一組樣式，其餘畫面版面完全重用既有商店畫面的樣式。

9男孩線：畫面異動總覽

  1. 選故事畫面（新）

    遊戲最先看到的畫面：既有玩家名單（選了直接進地圖，不用重選故事）+ 兩張故事卡「甜心少女的故事」／「改裝小車手的故事」。

  2. 建立角色畫面

    依選擇的故事只顯示對應 3 位角色（男孩：熱血男孩／酷酷男孩／陽光男孩），文案與按鈕字樣也依故事切換；新增「返回」按鈕回選故事畫面。

  3. 關卡地圖畫面

    男孩玩家看不到金幣徽章；原本「前往商店」的按鈕改成「查看我的改裝車庫」；頂欄小頭像顯示目前的車。六個關卡節點與過關/鎖定邏輯完全不變。

  4. 關卡結算畫面
    • 過關：沒有「前往商店」按鈕，只有「下一關」（全破則只有「查看結局」）；第二格統計從「獲得金幣」改成「改裝進度 N/6」。
    • 剛好解鎖烤漆顏色（過第四關）：結算卡片上直接多出現一排 3 顆選色球，點了當場看到車子變色，不用離開這個畫面。
    • 失敗：顯示「目前維持原樣」的車（車子沒有難過的畫面），按鈕與女生線一樣是「重新挑戰本關」／「結束本局」。
  5. 改裝車庫畫面（新，取代商店）

    大圖顯示目前的車、目前改裝階段文字說明；過第四關後多一區「烤漆顏色」，3 顆選色球隨時可切換（免費、即點即生效）；沒過第四關則顯示「通過第四關就能自訂烤漆顏色囉！」的提示。

  6. 結局畫面
    • 全破 6 關：顯示最終獎勵跑車（單一固定配色），文案改成男孩向的慶祝詞，沒有金幣統計、也沒有兔子熊入鏡。
    • 中途放棄：顯示「目前進度的車」套上灰階濾鏡（不是重置回破爛車），保留鼓勵文案的基調。

11男孩線：已知風險

  • 頭像圓形裁切依賴頭部位置：既有裁切效果假設頭在畫布上方置中；男孩+車的構圖若讓男孩偏一側，頭像會裁到車頂而不是臉。已在美術清單特別註明構圖要求，真的沒對齊也能用少量 CSS 補救，不必重畫。
  • 地圖頂欄迷你頭像偏小：車子構圖在極小尺寸下可能不易辨識，跟女生角色現況風險相同，先接受現況。
  • 同名但故事線不同的玩家：角色與故事線一旦建立無法更改；輸入既有名字會直接接手該玩家原本的故事線，只會提示一句、不會阻擋。

12男孩線：驗證方式

先測女生線迴歸（含用「修改前」建立的舊存檔開新版程式碼，確認沒有 track 欄位時仍正常運作），再測男孩線完整流程：

  1. 選「改裝小車手的故事」→ 3 張男孩卡、頭像看得出是臉不是車頂。
  2. 建立男孩角色 → 地圖沒有金幣徽章、次要按鈕文字是「查看我的改裝車庫」。
  3. 過關前進車庫 → 顯示破爛車、進度 0/6、烤漆區塊顯示「通過第四關」提示、沒有選色球。
  4. 依序過第 1～3 關，車庫與結算畫面的車子同步變成「修好但髒 → 洗乾淨 → 新輪框」。
  5. 過第 4 關 → 結算卡出現選色球，點選後當場看到車子變色，且「下一關」按鈕仍可正常點擊；回車庫、重新整理頁面，剛選的顏色都要保留。
  6. 過第 5 關 → 套件加上去且維持選定顏色；車庫改選別的顏色，套件版本也要跟著換色。
  7. 過第 6 關 → 結算卡與結局都是全新跑車、結局畫面只有男孩+車、文案是男孩向、無金幣統計。
  8. 重新開始 → 車子回到 stage 0、車庫烤漆區塊回到「通過第四關」提示。
  9. 故意在某關答錯太多次 → 結算卡顯示「目前維持原樣」的車，選「結束本局」→ 結局畫面顯示「目前進度的車 + 灰階」，不是重置回 stage 0。
  10. 手機寬度下檢查選故事畫面、建立角色畫面（6 選 3）、結算卡內嵌選色列、車庫畫面，確認沒有橫向溢出或按鈕被裁切。
